# Echo 开发踩坑记录

**Q：为什么直接迁入上游代码后前端无法构建？**

A：删除页面和 API 后，聊天过程组件仍引用旧类型，图片上传结果也沿用了不同字段名。解决方式是先以 TypeScript 编译作为依赖扫描，再统一 `ToolRun` 状态和上传 DTO。

**Q：为什么后端静态检查通过，测试收集却失败？**

A：`document_service` 的导入只有在测试加载时才执行，而迁移中误删了 `app/core/storage`。静态编译不会验证所有运行时导入路径，因此需要至少执行一次 pytest collection。

**Q：为什么不能保留上游项目的 Alembic 历史迁移？**

A：历史迁移会创建音乐、情绪、群聊、定时任务等已删除表。Echo 作为新项目应建立当前 ORM 对应的单一初始迁移，否则新环境仍会得到一套“幽灵数据库结构”。

**Q：为什么 Beat 和 Worker 要分开？**

A：Beat 只在每天 08:00 派发新闻任务，Worker 才负责联网检索、模型调用、邮件发送以及其他异步处理。独立部署可以避免耗时生成阻塞调度时钟。

**Q：为什么给已有数据库补功能时，新增布尔字段必须有默认值？**

A：新 ORM 中的 Python 默认值只影响以后创建的对象，不能填充数据库里已有行。直接增加 `NOT NULL` 的 `human_mode`、`show_avatar` 等列，会让升级因旧记录没有值而失败。迁移中应提供数据库端的 `false` 默认值，保证老用户升级后仍能正常读取原有会话和配置。
