# Echo 开发踩坑记录

**Q：为什么直接迁入上游代码后前端无法构建？**

A：删除页面和 API 后，聊天过程组件仍引用旧类型，图片上传结果也沿用了不同字段名。解决方式是先以 TypeScript 编译作为依赖扫描，再统一 `ToolRun` 状态和上传 DTO。

**Q：为什么后端静态检查通过，测试收集却失败？**

A：`document_service` 的导入只有在测试加载时才执行，而迁移中误删了 `app/core/storage`。静态编译不会验证所有运行时导入路径，因此需要至少执行一次 pytest collection。

**Q：为什么不能保留上游项目的 Alembic 历史迁移？**

A：历史迁移会创建音乐、情绪、群聊、定时任务等已删除表。Echo 作为新项目应建立当前 ORM 对应的单一初始迁移，否则新环境仍会得到一套“幽灵数据库结构”。

**Q：为什么删除 Beat 后仍保留 Celery？**

A：Beat 是周期调度器，Worker 是异步执行器。Echo 不需要定时主动任务，但文档解析、图片识别、记忆萃取和反思仍不应阻塞 HTTP 请求。

**Q：为什么品牌替换不能只改页面标题？**

A：应用名还存在于包名、锁文件、数据库默认名、ES 索引、容器名、日志路径、LocalStorage key、Nginx 证书和图片资源中。只改 UI 会留下部署冲突和数据串用风险。

**Q：为什么 API 镜像构建很久，而且上游镜像能达到近 20 GB？**

A：Docling 会依赖 PyTorch，默认 PyPI 的 Linux 包又会拉取 CUDA、cuDNN、NCCL 和 Triton。个人部署并不使用 GPU，却会为整套 GPU 运行时付出下载和磁盘成本。解决方式是保留 Docling，同时把 `torch` 与 `torchvision` 显式锁到 PyTorch CPU 仓库；Echo 的 API 镜像最终约 0.81 GB。

**Q：为什么测试全过，API 容器启动时仍报已删除的定时任务模块？**

A：Agent 内置工具通过 `__init__.py` 的导入副作用完成注册，删除 `schedule.py` 后入口文件还保留了导入。已有测试没有覆盖完整应用启动路径，因此 Docker 集成启动才暴露问题。裁剪模块后必须检查注册器、路由聚合和包入口，而不能只搜索业务调用方。

**Q：为什么 Web 镜像构建成功，容器却一启动就退出？**

A：上游 Nginx 默认配置把本地环境也强制跳转到 HTTPS，并直接加载服务器证书；镜像构建不会验证运行时证书是否存在。Echo 将基础配置改为 HTTP，把 HTTPS 与证书挂载拆到生产覆盖配置，本地 `docker compose up` 不再依赖证书文件。

**Q：为什么第一次裁剪后，功能看似简洁却偏离了真实需求？**

A：把“本阶段暂不开发”误判成“产品永远不需要”，会把深度研究、角色卡、Skills、群聊、Trace 等依赖链一起移除。实际使用时，用户会在配置页找不到 Verifier 模型、在聊天页找不到人物协作，也无法回看一次回答的成本。修正时不能只复制页面：还必须同步恢复 API 路由、服务编排、ORM 模型、迁移和导航入口，并逐项排除情绪、音乐、社区和定时调度这些真正不需要的能力。

**Q：为什么给已有数据库补功能时，新增布尔字段必须有默认值？**

A：新 ORM 中的 Python 默认值只影响以后创建的对象，不能填充数据库里已有行。直接增加 `NOT NULL` 的 `human_mode`、`show_avatar` 等列，会让升级因旧记录没有值而失败。迁移中应提供数据库端的 `false` 默认值，保证老用户升级后仍能正常读取原有会话和配置。
