# Echo 高频面试问答

**Q1：为什么用 PostgreSQL、Elasticsearch、Neo4j、Redis 四种存储？**

A：它们分别承担事务数据、向量/全文检索、关系图谱和缓存/任务队列。用单一数据库可以减少组件，但会让检索、图遍历或异步任务中的至少一项明显退化。

**Q2：父子块为什么不重叠？**

A：当前 MVP 用 1024 字符父块和 256 字符子块先观察效果。子块负责精确召回，父块负责回答上下文；不重叠可以减少小数据量下的重复向量和重复命中。

**Q3：RRF 后为什么还按 parent_id 聚合？**

A：RRF 合并的是不同召回通道的排名，同一父块可能有多个子块命中。按 parent_id 聚合可以避免把相同上下文重复塞给模型，同时保留该父块最强命中分数。

**Q4：记忆为什么要保留 Dialogue、Chunk、Statement？**

A：实体事实可能被模型萃取错。溯源层能回答“这条记忆来自哪次对话的哪句话”，为纠错、删除和可靠性评分提供依据。

**Q5：Function Calling 和 ReAct 为什么都保留？**

A：原生 Function Calling 对强模型更稳定；部分兼容模型没有可靠工具调用能力。ReAct 作为降级路径，让系统不被单一模型协议锁死。

**Q6：删除 Celery Beat 后，为什么还能生成每日回顾？**

A：Beat 只负责“到点触发”，不是任务执行器。Echo 在用户打开仪表盘或点击重新生成时投递普通 Celery 任务，由现有 Worker 执行，因此不需要周期调度器，也不需要增加第八个容器。

**Q7：每日回顾为什么要先返回统计文案，再异步调用模型？**

A：仪表盘首屏不应被模型延迟或配置错误阻塞。接口先返回可用的统计摘要，Worker 再使用用户默认对话模型润色，前端轮询更新；模型不可用时统计文案仍是完整降级结果。

**Q8：为什么自动化 UI 风格扫描不能直接按命中数量清零？**

A：扫描器只能识别模式，不能判断语义。圆形头像、在线状态点、工具来源图标和用户主动选择的 emoji 都可能被规则命中，但它们承担真实的信息功能。正确做法是先用扫描器定位高风险区域，再人工区分装饰性噪声和功能性表达，避免为了分数破坏可用性。

**Q9：删除未使用 CSS 为什么也属于前端架构治理？**

A：失效样式不会直接影响当前页面，却会持续制造误导、增加扫描噪声，并让后续开发者误用旧的渐变、玻璃或大阴影模式。确认没有组件引用后删除这些样式，可以缩小维护面并让设计规范更容易长期保持一致，而且不改变业务行为。
